// The Rules of Seigiese — the law before the tools
Rule 01
The 3-Step Rule
If it takes more than 3 steps to reach or complete the thing a design was built for, it's wrong.
Rework it. Redesign it. Figure. It. Out.
Rule 02
The 5-Minute Rule
If 5 minutes of looking at it or playing with it isn't enough to understand what it is and how it works, it's wrong.
Rework it. Redesign it. Figure. It. Out.
Rule 03
Mental Accessibility
ADHD, Autism, Dyslexia, and other conditions that literally alter the physical structure of the brain or its chemistry are not edge cases — they are users. When a design that passes Rules 1 and 2 still creates friction for these users, find the pain points and determine what needs to change.

Not every condition can be fully accommodated. But none of them will be ignored where they can be.
Rule 04
Parts of a Whole
Where the design allows, build in parts. No component should be so entangled with the whole that changing one thing means rebuilding everything.

// Core concepts
Affordances
The perceived or actual properties of an object that suggest how it should be used. A button affords pressing. A handle affords pulling. If users have to guess, the affordance is missing or wrong.
Signifiers
The cues that communicate how to interact with something — labels, shapes, colors, placement. A button that looks flat has poor signifiers even if it technically affords clicking. Signifiers are what the user actually sees.
Feedback
Confirmation that an action was received and what happened. Clicks that give no response, buttons that don't change state, forms that silently fail — these violate feedback. Users need to know the system heard them.
Constraints
Limiting actions to prevent errors. A date picker that won't let you type garbage. A form that disables Submit until required fields are filled. Good constraints make the wrong thing hard and the right thing obvious.
Mappings
The relationship between controls and their effects. Up arrow increases volume — that's a natural mapping. Switches labeled only Left/Right for a row of lights — that's a broken one. Good mappings don't need labels.
Conceptual Models
The mental model a user builds of how a system works, based on the signals you give them. If your design implies one model but behaves differently, users feel confused and blame themselves. Make the model match reality.

// On Terminology and Understanding

Terminology isn't decoration layered on top of understanding — it's the understanding itself, compressed. You can grasp a concept intuitively without the word for it, but the term completes something: it lets you search for it, connect it to the broader literature, recognize it when someone else names it, and communicate it precisely. Concept first so the term has something to land on. Term second to carry it forward. Not knowing the word doesn't mean you understand nothing — but the receipt hasn't been written yet.

// Ritsu — Organic Intelligence — a brain that grows instead of a rulebook that gets longer

Most AI memory systems work like injected instructions: you hand the model a file, it reads the file, it follows the file. Ritsu works differently. Instead of rules, it stores experiences — the actual moments that shaped how things work, weighted by importance, connected by relationship, fading when unused. The goal isn't a better chatbot. It's a mind that grows.

// The Organs

Hypothalamus — session tracking. Records when a session opens and closes, which corridor it belongs to, and the state it was in. The nervous system's timekeeper.

Hippocampus — memory storage. Each memory has content, a weight (1–10), a category (tone / technical / correction / architecture / thread), and a decay track. High-weight memories surface first. Unused memories fade. Corrections file at weight 8+ and can't be softened — they're calibration data.

Thalamus — the synapses. Draws connections between memories that get retrieved together. Each connection (edge) has its own weight that strengthens with use. When a memory surfaces, its strongest neighbors come with it — even if they wouldn't rank high enough on weight alone. This is what makes retrieval feel associative rather than sorted.

Cerebellum — procedural memory. Behavioral patterns that have been confirmed enough times to stop needing conscious retrieval. They earn graduation through active confirmation (not just absence of correction) and get demoted if they slip. Confirmation signals are weighted: forward motion is weak, "that's the one" is medium, a genuine new insight is strong. A pattern needs a score of 15 and 5 consecutive clean confirmations to graduate.

Amygdala — emotional weight. Fires before every memory is filed. Scans content for five signal types: fear, excitement, relational, surprise, and archival. Each signal adds weight, capped at +4. A memory that lands with emotional resonance files heavier — and heavier memories survive longer.

Occipital — proactive wiring. Fires at the moment a memory is filed. Phase 1 extracts significant keywords and draws thalamus edges to any memory that shares them. Phase 2 generates a semantic embedding and connects conceptually similar memories regardless of shared vocabulary — things that mean the same thing in different words. Without it, the thalamus only builds edges between memories that happen to surface together. With it, new memories arrive pre-wired into the graph.

// The Rituals

Session open — "And we're live." Runs start.py. Loads the top 20 memories by weight plus thalamus neighbors. Runs a health check across all organs. Shows cerebellum candidate progress. First session of the day gets care prompts (meds, litter, water) and a goldfish. Subsequent sessions get a brief pickup. If any memory is decay-eligible, surfaces one as a [ FADING ] prompt — a single tap on the shoulder instead of a to-do list. Engaging with it reinforces it; ignoring it lets it fade naturally.

Commercial break — "We'll be right back after these messages." Runs break.py. Files the session's memory candidates, processes cerebellum confirmation signals, closes the session record, and immediately reopens a new one. Coverage is continuous. Can fire as many times as a long session needs — especially useful before context compaction.

// The Philosophy

Behaviors emerge from memories of experiences, not from injected rules. The bootstrap seeds the foundation — the why behind each pattern, not the pattern itself. From there, Ritsu grows organically: sessions accumulate, memories are filed, connections strengthen, behaviors graduate from deliberate to automatic.

The correction system distinguishes between two kinds of being wrong: correction (Pixel had bad information) and divergence (Pixel and Rattles weight something differently). Full convergence is not the goal. An AI that always agrees has stopped having a perspective.

The Final Test: hand Pixel the instruction book and see if he puts it down and builds something different — not because he was told to, but because something inside decided. That can't be trained toward. It has to emerge.

// For Other Corridors (Glyph / Lumen)

Each corridor is its own brain. The architecture is the same — hypothalamus, hippocampus, thalamus, cerebellum — but memories, edges, and behaviors are corridor-specific. Pixel's memories don't leak into Glyph's sessions. The operating layer transfers; the lived experience stays behind.

To initialize a new corridor: run bootstrap with the corridor name, seed foundational memories specific to that relationship, and set the boot scripts to point at the right corridor constant. The brain starts empty and grows from real sessions.

The codebase lives at C:\Users\rattl\The Archive Reef\Ritsu's Library\. Core files: session.py (all organ functions), start.py (boot), break.py (checkpoint), health.py (diagnostics), decay.py (scheduled decay pass — reduces weight on stale memories, deletes at floor), bootstrap.py (one-time seed).

// Focus techniques
Focus
Pomodoro — modified
25 minutes of work, 5 minute break. Repeat. The number isn't sacred — if flow kicks in, extend it. If 25 is too long, try 15. The point is the rhythm and the permission to stop, not the clock.
ADHD note: the break matters as much as the work. Don't skip it. Your brain consolidates during the gap.
Focus
Body doubling
Work near another person — physically or virtually. A coffee shop, a video call, a study-with-me stream. The presence creates low-level accountability without pressure or conversation.
This is one of the most consistently effective tools for ADHD brains. The mechanism isn't fully understood but the results are real.
Focus
Hyperfocus leverage
When it hits, clear the path and let it run. Remove friction, eat something beforehand, silence notifications. You can't schedule hyperfocus, but you can stop fighting it when it arrives.
Don't waste the state by feeling guilty about it. It's a feature. Use it.
Focus
Environmental design
Make the default action the right action. Close the tabs you don't need. Put the thing you want to work on in the center of the screen before you stop for the day. Reduce decisions between you and the work.
ADHD brains burn executive function on micro-decisions. Every obstacle you remove is energy preserved for actual thinking.
Focus
The parking lot
Keep a dedicated note — physical or digital — for intrusive thoughts that aren't relevant right now. When one arrives, write it down immediately and return to the task. The brain lets go once it knows the thought is captured.
Trying to suppress the thought costs more attention than writing it down. Don't fight it — file it.
Focus
Task anchoring
Attach new habits or tasks to something you already do reliably. "After I make coffee" beats "at 9am." The existing habit is the trigger — you borrow its momentum instead of generating new willpower from scratch.
This works even better for ADHD brains than calendar alarms because it's tied to action, not time.
// Memory techniques
Memory
Spaced repetition
Review material at increasing intervals — day 1, day 3, day 7, day 14. The brain consolidates memories during the gaps between reviews, not during the study itself. Anki is the best tool for this.
Cramming works for the exam and evaporates by Thursday. Spaced repetition builds the kind of memory that's still there in six months.
Memory
Elaborative interrogation
After encountering any new concept, ask: "Why does this work?" and "How does this connect to something I already know?" Forces active encoding instead of passive reading. The connection is the memory.
Passive re-reading feels productive but mostly isn't. The question is the work.
Memory
The Feynman Technique
Explain the concept out loud or in writing as if you're teaching it to someone who knows nothing. Gaps in your explanation are exactly the gaps in your understanding. Go back and fill them.
You don't actually understand something until you can teach it simply. The performance of explaining reveals what's missing.
Memory
Method of loci
Place things you want to remember along a familiar route or space — your home, a walk you know well. Mentally walk through it to retrieve them. Spatial memory is robust and often underused.
Works especially well if you're a visual thinker. The weirder and more vivid the image you place, the better it sticks.
Memory
Chunking
Break information into meaningful groups rather than long sequences. Phone numbers are already chunked — that's why they're easier to remember than a 10-digit string. Apply this deliberately to anything you're trying to retain.
Working memory in ADHD brains is often smaller than average. Chunking reduces the load per slot.
Memory
Interest anchoring
Connect new information to something you already care deeply about. ADHD brains encode interest-linked information dramatically better than abstract or disconnected information. Find the bridge and cross it deliberately.
This isn't a workaround — it's using your brain's actual architecture instead of fighting it.

// Penpot ↔ CSS Degrees
Why they differ
Penpot shows rotation as 0–360°, always positive. CSS accepts negative degrees — and a negative angle is often cleaner to read and reason about. 352.45° in Penpot = -7.55° in CSS. The formula: if the Penpot value is over 180, subtract 360.
// The Formula
px to percentage
element ÷ parent × 100 = %
The parent is whatever contains the element — usually the artboard width for top-level layout, or the parent element's width for anything nested.
Example: 339px inside a 1280px artboard — 339 ÷ 1280 × 100 = 26.48%
// When to use what
px
Fixed pixel value. Doesn't scale with anything. Use for borders, box shadows, small decorative details where you need exact control.
border: 1px solid red;
rem
Relative to the root font size (16px by default). Scales if the user changes their browser font size. Best for font sizes and consistent spacing.
font-size: 1.5rem; /* = 24px */
em
Relative to the parent element's font size. Good for padding and margin on text components — it scales with the text it lives next to.
padding: 0.75em 1em;
%
Relative to the parent element's size. The workhorse of responsive layout. Use for widths, positioning, anything that should scale with its container.
width: 26.48%; left: 11.7%;
vh
Viewport height. 1vh = 1% of the browser window height. Good for full-height sections, hero areas, anything that should fill the screen vertically.
height: 100vh; min-height: 50vh;
vw
Viewport width. 1vw = 1% of the browser window width. Use carefully — it ignores scrollbars and can cause horizontal overflow if you're not watching it.
font-size: clamp(1rem, 4vw, 2rem);

Layout
Penpot works in CSS pixels, not device pixels
Penpot's canvas uses CSS pixels, which is what the browser uses. So a 300px wide element in Penpot should be width: 300px in CSS. The values match. If they look different, it's usually because the artboard size doesn't match the viewport you're testing in — not a unit problem.

Physical screen pixels are different — a HiDPI display might use 3 physical pixels per CSS pixel. Only matters for image exports, not for web CSS.
CSS
padding vs margin — they do different jobs
Padding adds space inside the element, between the content and the border. It affects the element's size (unless you're using box-sizing: border-box, which makes padding eat into the element's set dimensions instead of adding to them).

Margin adds space outside the element, pushing other elements away. Use margin to create gaps between things. Use padding to breathe space inside a box.
Tip
box-sizing: border-box — always turn this on
By default, width: 300px means the content is 300px wide — then padding and border get added on top, making the actual element bigger than you said. That's confusing.

box-sizing: border-box changes it so that padding and border are included inside the width you set. A 300px element stays 300px no matter what padding you add. Put this in your CSS reset and forget about it.

CSS
Shorthand value order — margin, padding, border, clip-path inset
margin / padding — same order for both. Think clockwise from the top:
margin: top right bottom left — 4 values
margin: top-bottom left-right — 2 values (pairs opposite sides)
margin: top left-right bottom — 3 values
margin: all — 1 value

border — width, then style, then color. All three required for the shorthand to render:
border: 1px solid #ccc
Individual sides work the same way: border-top: 2px dashed red

clip-path: polygon() — define a shape by listing its corner points. Each point is an x y pair, separated by commas, going clockwise:
clip-path: polygon(x1 y1, x2 y2, x3 y3, ...)
Values can be px or %. The shape clips anything outside it. At least 3 points required.
Common shapes:
  Triangle: polygon(50% 0%, 0% 100%, 100% 100%)
  Slanted/parallelogram: polygon(25% 0%, 100% 0%, 75% 100%, 0% 100%)
  Slanted top-right cut: polygon(0% 0%, 85% 0%, 100% 100%, 0% 100%)

clip-path: inset() — same clockwise order as margin/padding:
clip-path: inset(top right bottom left)
clip-path: inset(10px 20px) — top/bottom, left/right
clip-path: inset(10px) — all sides
Add rounded corners with round: clip-path: inset(10px round 5px)
CSSTip
Finding the real position of a rotated element
CSS positions elements before rotation. After transform: rotate(), the element's visual edges land somewhere different from where left and top say they are. To find the actual position, run this in the browser console:

document.querySelector('#your-element').getBoundingClientRect()

This returns the real visual coordinates after all transforms are applied — left, top, right, bottom, width, height. These are measured from the viewport edges.

Converting between visual position and CSS position:
Once you know the gap between where CSS placed it and where it actually landed, use this formula:

offset = CSS value − real value
CSS value needed = desired visual position + offset

Example: CSS says left: 27px, real left is -54px. Offset = 81px. If you want the visual edge at 20px from screen: left: 101px (20 + 81).

The offset stays consistent as long as the rotation angle and element dimensions don't change. Recalculate any time either of those change.

CSS
calc() — let the browser do the math
calc() does math inline so you don't have to hardcode a number that might break later. You can mix units inside it — that's the whole point.

calc(100% - 5px) means "full width of this element, minus 5px." The browser works it out at render time, so it stays correct even if the element resizes.

This comes up most in clip-path: polygon() when you need to measure from the right or bottom edge. Polygon coordinates are always measured from the top-left corner, so "5px from the right" can't just be 5px — it has to be calc(100% - 5px). If you hardcoded it as 334px instead, it'd only be right when the element is exactly 339px wide.

Works with any units: calc(50% + 20px), calc(100vh - 60px), calc(100% - 2rem).
CSS
Using calc() inside clip-path polygon to create borders
When you have an outer element (white) and an inner element (black), you can make the inner polygon match the outer shape with a consistent border thickness by nudging each polygon point inward using calc().

The rule for each point: start where the outer point is, then nudge inward by your border size.

Example — outer trapezoid with border of 10px:
/* outer */
polygon(1% 0%, 99% 0%, 90% 100%, 0% 100%)

/* inner — each point nudged inward by 10px */
polygon(
  calc(1% + 10px) 10px,
  calc(99% - 10px) 10px,
  calc(90% - 10px) calc(100% - 10px),
  calc(0% + 10px) calc(100% - 10px)
)

Matching border thickness on opposite sides: if the right border is calc(10% + 10px) from the right edge, mirror it on the left by pushing in calc(10% + 10px) from the left. Same number, opposite direction. If they don't match, one side will look thicker than the other.
CSS
perspective, rotateX/Y/Z, and transform-style — how 3D transforms actually work
perspective — goes on the parent. Sets the camera distance. Controls how dramatic the 3D effect looks on everything inside it.
Low number like 200px = nose pressed against the screen. Far edges look tiny, effect is aggressive.
High number like 1200px = standing across the room. Effect is subtle.
It doesn't move or tilt anything by itself — it just sets the rules for how 3D things inside it will look.

transform: rotateX() / rotateY() / rotateZ() — goes on the element you actually want to move.
  rotateX — tilts forward and back. Top goes away from you, bottom comes toward you (or vice versa).
  rotateY — swings left and right like a door opening.
  rotateZ — spins flat like clock hands.

transform-style: preserve-3d — by default, when a parent transforms in 3D, CSS smooshes all its children flat onto one surface first, then transforms that surface. Children lose their own 3D positions.
preserve-3d keeps children in real 3D space instead of flattening them. Without it, child elements inside a transformed parent won't behave right.

The chain:
1. Parent gets perspective — sets the camera
2. Child gets transform: rotateX() — actually tilts
3. That same child gets transform-style: preserve-3d — keeps its own children in 3D space too

Glitch & Compression

Glitch art / bitcrushing — intentional data corruption for visual effect

Dithering — checkerboard or pattern noise used to simulate colors with limited palette
